## 1. TL;DR

Phase A v1.6 đã ship 2 advisory criteria (`NO_SCREENSHOTS_UI` / `NOT_REBASED`).
B14/B15 cards đã deploy nhưng **render trống** vì 3 nguồn gap:

| Gap | Hệ quả | Root cause |
|---|---|---|
| `has_screenshots = false` (0/26780 MRs) | B14 empty | Field tính từ `description` lúc extract. Raw layer không lưu `description` → không backfill được. Cần re-extract. |
| `diverged_commits_count IS NULL` (0/26780 MRs) | B15 empty | Cần param `include_diverged_commits_count=true` (v1.6 mới) trên single-MR endpoint. Chưa re-extract sau migration 014. |
| `is_ui_related = false` (0/26780 MRs) | B14 vẫn empty kể cả khi re-extract | Heuristic dựa label_names. Dataset hiện không có label nào match `(ui\|front\|mobile\|design\|css)`. Top labels: `ai-review`, `ai-assisted`, `complexity::*`, `role::*`. |

Khắc phục cần 2 hướng:
1. **Re-extract incremental** lấp 2 gap đầu (XS effort, mở đường cho B15).
2. **CI quality gate** lấp gap 3 + thêm signals khác mà API không có (LOC-diff UI detection, secret scan, linter, test-added).

## 3. Tiêu chí v1.6 chưa codify trong spec (potential future)

Guide hiện vẫn là v1.4 (`MR_Compliance_Guide_v1.4.md`). v1.6 chỉ bump spec, chưa có Guide v1.6.
Các tiêu chí dưới đây thường được đề cập trong code review thực tế nhưng chưa có data source:

| Code đề xuất | Mô tả | Nguồn signal khả thi |
|---|---|---|
| `SECRET_LEAKED` | Hardcoded API key / token / password trong diff | gitleaks/trufflehog trên CI |
| `LINTER_FAILED` | Lint không pass (eslint/pylint/golangci-lint) | CI job exit code |
| `NO_TESTS_ADDED` | MR ≥100 LOC nhưng không có test file | git diff + filename pattern |
| `BREAKING_NOT_DOCUMENTED` | Title có `!:` (Conventional Commits breaking) mà không có `BREAKING CHANGE:` trong body | Parse extractor (đã có `is_breaking`, cần thêm field) |
| `DEPS_CHANGED_UNREVIEWED` | Touch `package.json` / `requirements.txt` mà không có security reviewer | CI diff + reviewer_usernames join |
| `UI_NO_SCREENSHOT_FILEPATH` | MR đụng `*.tsx`/`*.vue`/`*.css` (không cần label) mà không có screenshot | CI diff (broader than label heuristic) |

Các code này **chưa nằm trong `compliance_spec.yaml`** — sẽ add khi CI quality gate ship.

## 4. CI Quality Gate — Architecture

### 4.1 Mục tiêu

GitLab CI job chạy trên mọi MR pipeline, collect signals mà GitLab API không trả về, post về backend qua webhook → dbt → Metabase.

### 4.2 Data flow

```
GitLab MR pipeline
  └─ stage: compliance-gate
       └─ scripts/compliance_gate.py
            ├─ git diff --name-only (file paths)
            ├─ git rev-list --count HEAD..origin/<target>
            ├─ gitleaks detect (secrets)
            ├─ language detector → lint runner
            └─ HTTP POST /webhook/ci-gate (FastAPI)
                  └─ INSERT INTO gitlab_raw.mr_ci_signals
                        └─ dbt stg_mr_ci_signals (pivot)
                              └─ JOIN v_compliance_mgmt
                                    └─ Metabase cards
```

### 4.3 Schema (migration 015 — proposed)

```sql
CREATE TABLE IF NOT EXISTS gitlab_raw.mr_ci_signals (
    project_id      bigint       NOT NULL,
    mr_iid          bigint       NOT NULL,
    pipeline_id     bigint,
    signal_name     text         NOT NULL,
    signal_value    jsonb        NOT NULL,
    captured_at     timestamptz  NOT NULL DEFAULT now(),
    PRIMARY KEY (project_id, mr_iid, signal_name, captured_at)
);
CREATE INDEX idx_mr_ci_signals_mr ON gitlab_raw.mr_ci_signals (project_id, mr_iid);
CREATE INDEX idx_mr_ci_signals_captured ON gitlab_raw.mr_ci_signals (captured_at DESC);
```

`signal_value` jsonb để mỗi signal tự do schema (bool, int, list of paths, finding objects).

### 4.4 Webhook endpoint mới

Thêm vào `src/webhook/app.py`:

```python
@app.post("/webhook/ci-gate")
async def ci_gate(payload: CiGatePayload, x_gate_token: str = Header(...)):
    if not verify_ci_gate_token(x_gate_token):
        raise HTTPException(401)
    persist_ci_signals(payload)
    return {"ok": True}
```

Token mới: `CI_GATE_WEBHOOK_TOKEN` env var (HMAC shared secret với CI runner).

### 4.5 `scripts/compliance_gate.py` skeleton

```python
def collect_signals(mr_iid, project_id, target_branch):
    changed = git_diff_files(target_branch)
    return {
        "changed_files":           changed,
        "is_ui_related_files":     any(re.search(r"\.(tsx|jsx|vue|css|scss|html)$", f) for f in changed),
        "diverged_commits_real":   git_rev_count(f"HEAD..origin/{target_branch}"),
        "has_screenshot_uploads":  has_image_in_description(fetch_mr_description(mr_iid)),
        "secret_scan_findings":    run_gitleaks(),
        "linter_status":           run_linter(detect_language(changed)),
        "test_files_added":        sum(1 for f in changed if is_test_file(f)),
        "mr_size_real":            git_diff_loc(target_branch),
    }
```

### 4.6 `.gitlab-ci.yml` integration (downstream projects)

```yaml
include:
  - project: 'engineering/ci-templates'
    file: '/compliance-gate.yml'

compliance-gate:
  stage: compliance
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
  allow_failure: true       # advisory phase — không block merge
  variables:
    COMPLIANCE_GATE_URL: $CI_COMPLIANCE_GATE_URL
    COMPLIANCE_GATE_TOKEN: $CI_COMPLIANCE_GATE_TOKEN
  script:
    - python scripts/compliance_gate.py
        --mr-iid $CI_MERGE_REQUEST_IID
        --project-id $CI_MERGE_REQUEST_PROJECT_ID
        --target-branch $CI_MERGE_REQUEST_TARGET_BRANCH_NAME
```

`allow_failure: true` ở giai đoạn advisory; khi promote v1.7 → bỏ flag, gate sẽ block merge nếu BLOCKER signal fail.

### 4.7 dbt staging

```sql
-- stg_mr_ci_signals.sql (pivot latest signal per MR)
with latest as (
    select project_id, mr_iid, signal_name,
           signal_value, captured_at,
           row_number() over (partition by project_id, mr_iid, signal_name
                              order by captured_at desc) as rn
    from {{ source('gitlab_raw', 'mr_ci_signals') }}
)
select
    project_id,
    mr_iid,
    max(case when signal_name = 'is_ui_related_files'   then (signal_value::text)::boolean end) as is_ui_related_files,
    max(case when signal_name = 'has_screenshot_uploads' then (signal_value::text)::boolean end) as has_screenshot_uploads,
    max(case when signal_name = 'diverged_commits_real'  then (signal_value::text)::int     end) as diverged_commits_real,
    max(case when signal_name = 'secret_scan_findings'   then (signal_value::text)::int     end) as secret_scan_findings,
    max(case when signal_name = 'linter_status'          then (signal_value::text)::text    end) as linter_status,
    max(case when signal_name = 'test_files_added'       then (signal_value::text)::int     end) as test_files_added
from latest where rn = 1
group by 1, 2
```

### 4.8 Join into `v_compliance_mgmt`

CI signal wins over extractor-derived khi present (CI có ground-truth từ git, không phụ thuộc label):

```sql
coalesce(cs.is_ui_related_files,   mr.is_ui_related)   as is_ui_related,
coalesce(cs.has_screenshot_uploads, mr.has_screenshots) as has_screenshots,
coalesce(cs.diverged_commits_real,  mr.diverged_commits_count) as diverged_commits_count,
cs.secret_scan_findings,
cs.linter_status,
cs.test_files_added
```

## 5. Phase Plan

| Phase | Scope | Effort | Owner | Outcome |
|---|---|---|---|---|
| **A.1** | Re-extract last 60d với `include_diverged_commits_count=true` đã có sẵn từ commit 8e47b3f | XS | extractor | B15 bắt đầu có data cho recent MRs |

## 6. Acceptance criteria

Để coi "B14/B15 có data thật":
- **B14**: `is_ui_related = true` count ≥ 50 / tuần trong 4 tuần liên tiếp → `screenshot_pct` render được.
- **B15**: `diverged_commits_count IS NOT NULL` cho ≥ 80% MRs merged trong window → `rebase_pct` render được.

Để coi "CI gate live":
- ≥1 signal/MR cho ≥ 90% MRs trong 7 ngày.
- Webhook 5xx rate < 1%.
- New cards B16 (Secret findings), B17 (Linter pass rate), B18 (Test added rate) render data.

## 7. Risks & open questions

| Risk | Mitigation |
|---|---|
| CI runner phải có DB access hoặc network access vào webhook host | Webhook public/internal? Cần xác định trước B.1. |
| gitleaks báo false positive nhiều → CI noise | Phase advisory `allow_failure: true`, tune ruleset trước khi promote. |
| Signals từ failed pipeline (CI never reached compliance-gate) | Fallback to extractor-derived (already coalesced). Compliance gate là enrichment, không thay thế. |
| Multi-language repos → linter detector phức tạp | Phase B.2 ship với Python+JS only, mở rộng sau. |
| Token leak qua CI log | Mask qua GitLab CI variable masking + HMAC validation server-side. |
